First step in any box we attack is Enumeration. First identify what you already know. For Nibbles we know the IP address, the server OS type, and that it has a web related attack vector. Given what we know about it so far, this makes it a **grey-box** because we have some, though not all information on the target. lets quickly review black, grey, and white box engagements

| Engagement    | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Black-Box** | Low level to no knowledge of a target. The penetration tester must perform in-depth reconnaissance to learn about the target. This may be an external penetration test where the tester is given only the company name and no further information such as target IP addresses, or an internal penetration test where the tester either has to bypass controls to gain initial access to the network or can connect to the internal network but has no information about internal networks/hosts. This type of penetration test most simulates an actual attack but is not as comprehensive as other assessment types and could leave misconfigurations/vulnerabilities undiscovered. |
| **Grey-Box**  | In a grey-box test, the tester is given a certain amount of information in advance. This may be a list of in-scope IP addresses/ranges, low-level credentials to a web application or Active Directory, or some application/network diagrams. This type of penetration test can simulate a malicious insider or see what an attacker can do with a low level of access. In this scenario, the tester will typically spend less time on reconnaissance and more time looking for misconfigurations and attempting exploitation.                                                                                                                                                       |
| **White-Box** | In this type of test, the tester is given complete access. In a web application test, they may be provided with administrator-level credentials, access to the source code, build diagrams, etc., to look for logic vulnerabilities and other difficult-to-discover flaws. In a network test, they may be given administrator-level credentials to dig into Active Directory or other systems for misconfigurations that may otherwise be missed. This assessment type is highly comprehensive as the tester will have access to both sides of a target and perform a comprehensive analysis.                                                                                        |
### [Nmap](../../../TTPs%20and%20Tools/Tools/Host%20Discovery%20and%20Scanning/Nmap.md) 
for our example we will use `nmap -sV --open -oA nibbles_intel_scan <TARGET_IP>` these flags are explained no the [Nmap](../../../TTPs%20and%20Tools/Tools/Host%20Discovery%20and%20Scanning/Nmap.md)  page. Notably we use `-oA` to make sure we're keeping extensive notes as we go. Build this skill early and often. Ensure you also keep timestamps along the way. For the box nibbles we find port 22 and 80 open. After an initial scan we can start a full scan with `nmap -p- --open -oA nibbles_full_tcp_scan <TARGET_IP>` This is to ensure we don't miss something on a non-standard port. While this runs in the background we'll do some [Banner Grabbing](../../../TTPs%20and%20Tools/Techniques/Enumeration/Banner%20Grabbing.md) with [Netcat](../../../TTPs%20and%20Tools/Tools/Connectivity%20and%20Port%20Interaction/Netcat.md) we run `nc -nv <TARGET_IP> <TARGET_PORT>`. For nibbles banner grabbing confirms [SSH](../../../TTPs%20and%20Tools/Tools/Remote%20Access/SSH.md) on port 22 running OpenSSH 7.2p2 but port 80 yields no results other than that it is a web server. At this point our full scan should be done and we can see that there are no other ports open. We can use Nmap common scripts to further enumerate these services and ports. Use the following to scan just the desired ports `nmap -sC -p 22,80 -oA nibbles_script_scan <TARGET_IP>` For nibbles, this doesn't give us anything new, but we can use a specific script to better enumerate port 80. run the following `nmap -sV --script=http-enum -oA nibbles_nmap_http_enum <TARGET_IP>`
